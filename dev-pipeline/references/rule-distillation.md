# 规则沉淀（任务结束前）

`delivery_ready` 后、最终回复前，如果用户纠正或 review/测试/子代理结果暴露反复出现的决策偏差，把它固化成**让下次默认做对**的持久规则，而不是只打一次性补丁。

- **提炼根因，不记流水账**：问"什么原则本可避免这次偏差",把具体事故抽象成可复用的判断,不写"这次某文件某行错了"这种一次性细节。
- **找对事实来源**：先定位该规则归哪个已有文档/约定/skill 拥有;读它,优先**改写/合并**进去,而不是新开一段。一个概念只在一处。
- **过四关再落**:可泛化(适用多次未来任务)、最小(不加冗余概念/流程)、连贯(契合既有结构和术语)、可执行(改变下次决策,不只是补全描述)。任一不过就不固化。
- **没有合适的拥有者**时,才建最小的新落点。
- 验证:改完重读该段,确认没留重复或矛盾,没为省事保留烂结构。

目标:不优化"记住过去",优化"下次默认做对"。
