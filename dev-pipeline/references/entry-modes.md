# 入口模式判定 · 边角规则

主判定见 `SKILL.md`「入口判定」。状态、事件和守卫条件以 `statechart.md` 为准；本文件只处理用户话术如何映射到入口模式。

- **完整流水线的适用面**：任务需要理解当前 repo、修改文件、审查 diff、调试行为、设计重构、补测试、更新技术文档或交付验证结果时，进入完整流水线。
- **高风险默认先方案**：重构、迁移、架构调整，且用户没明确要求交付改后的文件或行为时，先交付方案；用户确认写入后，按 `statechart.md` 重新进入实现入口。
- **上轮建议被接受**：上一轮已给出具体写入建议，本轮用户明确接受或要求继续时，视为交付物变成改后的文件；若不是单文件低风险任务，仍按 `PlanReview` / `PlanApproval` 推进。
- **初始授权只决定入口**：用户在首条请求里说“完整流程执行”“按完整计划执行”只能进入流程；后续计划批准按 `plan_approval_guard` 执行。
- **轻量任务只做入口豁免**：单文件低风险任务可进入轻量实现；是否满足轻量条件以 `implementation_light_guard` 为准。
- **确认类话术映射**：需求不清、操作有破坏性、权限/数据风险高或批准语义含糊时，进入 `WaitForUser` 或停在 `PlanApproval`；具体判断按 `side_effect_guard`、`side_effect_approval_guard` 和 `plan_approval_guard`。
- **`plan only` / `review only` 的硬约束**：用户明确这类约束时严格保持，只读不写；除非用户追加要求，不进入实现入口。
