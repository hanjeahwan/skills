# 入口模式判定 · 边角规则

主判定见 SKILL.md「理解输入与入口判定」。模式不明、或命中下面这些情形时按此处:

- **完整流水线的适用面**:任务需要理解当前 repo、修改文件、审查 diff、调试行为、设计重构、补测试、更新技术文档或交付验证结果时,用完整流水线。
- **高风险默认先方案**:重构、迁移、架构调整,用户没明确要求交付改后的文件/行为时,默认先交付方案;用户确认方案或要求写入后,再进实现模式。
- **上轮建议被接受**:上一轮已给出具体写入建议,本轮用户明确接受或要求继续,视为交付物变成改后的文件,进实现模式。
- **何时停下等确认**:只有进入实现模式且任务明显需要改代码/文件时,才默认推进到实现和验证;需求不清、操作有破坏性、权限/数据风险高,或用户明确要求先确认时,先停下等用户决定。
- **`plan only`/`review only` 的硬约束**:用户明确这类约束时严格保持,除非用户追加要求,不改文件。
