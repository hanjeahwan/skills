# 并行审查与验证（子代理委派）

可以在不改变本轮交付物模式的前提下启动子代理（spawn subagents / delegate，启动 subagent workflows / parallel agent work），用于受限的并行审查或独立验证，以及需要拆分但默认串行的执行任务。它不能绕过交付物判断、plan-first 规则、只读约束或等待确认条件；只要没有触发这些条件，不需要每次另行确认。子代理任务用于补充主线程判断；最终取舍仍由主线程负责。

- **触发条件命中即默认启动子代理**：触发条件见 SKILL.md「跨阶段规则·子代理委派」。命中任一就进入子代理启动路径，把这一步当作降低遗漏风险的质量门槛；只有明确命中跳过条件或异常降级条件时才留在主线程。
- **跳过须交代**：够不着量级门槛时，用一句话或任务记录说明不启动理由即可（单文件低风险、强耦合设计判断、需连续用户交互）。命中触发条件却不启动子代理时，必须说明工具失败、资源冲突或安全边界原因。低风险任务说明未命中门槛即可，不跑发现协议。
- **子代理输入用 skill 自带的 prompt 模板**：启动子代理时不读 host 注册的专用 agent，也不点名工具、subagent_type、agent 路径或模型；按下方「发现协议」从 `prompts/` 选模板，加本次具体输入喂给子代理，用当前宿主的子代理启动机制。这样行为跨环境一致、可测。
- 启动前先分清主线任务和旁路任务：主线程处理设计判断、用户沟通、diff review、合并顺序和最终验证；子代理任务只处理独立、可验证、不会替代主线程判断的部分。
- 子代理任务必须包含清晰输入、目标、范围、输出格式和读写边界。代码修改类任务必须指定可读文件、可写文件、参考模式、验证入口和结果格式，并提醒执行者不要 revert、stage、commit、push 或覆盖他人改动。
- 实现类拆分任务默认串行执行；并行只用于只读审查或独立验证。
- 启动前做冲突检查：确认任务不会覆盖用户已有改动，不会和主线程正在编辑的文件、生成物、测试环境、dev server、缓存目录或其它 runtime resource 冲突；有冲突时留在主线程串行处理。
- 使用子代理工具前，先确认不会递归进入同类 sandbox，且用户或项目配置允许。
- 不适合交给子代理的任务留在主线程：强耦合设计判断、紧急阻塞问题、需要连续用户交互的流程、或者结果必须由当前上下文直接决定的工作。
- 如果子代理工具调用失败、平台规则不允许本次调用，或安全边界与任务冲突，则执行本地第二轮审查或串行执行，并在最终回复说明未启动子代理的原因。

## 发现协议

启动子代理时不查中心表，按约定**发现**模板：

1. 列出 `prompts/` 下的文件。
2. 读每个文件头部的 H1 和「触发：…」行——那是它的自描述（角色 + 适用场景）。
3. 挑触发场景与当前子代理需求匹配的那一个，**只加载它一个文件**，把它整段（含焊死的只读边界）+ 本次具体输入喂给子代理。
4. 没有匹配的：现写 brief，但同样贴上只读边界（禁止 Edit/Write/revert/stage/commit/push，只回结论）。

## 计划 review 子代理委派（Stage 2 自动）

Stage 2 方案成型后，方案命中子代理委派触发条件（见 SKILL.md「跨阶段规则·子代理委派」）时，默认 fan-out 一组只读 review 子代理对**计划本身**做多视角审查，再回到关卡。进入 Stage 3 前，主线程至少要汇总一份计划 review 结果；如果任务强耦合、不能等待或子代理工具调用失败，记录原因并按下面四个 lens 做本地第二轮自审。窄范围低风险方案不 fan-out，主线程自审即可。

- 每个子代理只领一个视角（lens），并行执行，全部只读，绝不写文件：
  1. **行为回归与范围漂移**：方案会破坏哪些现有行为？范围是否偷偷扩大、漏掉受影响调用点？
  2. **状态流与副作用**：状态模型、side effect owner、异步顺序、非法/不可达状态是否处理。
  3. **contract 与边界**：API/schema/权限/数据流 contract 是否破坏；跨模块边界是否符合本 repo 既有实践。
  4. **验证充分性**：验证计划是否覆盖改动行为，缺哪些测试或静态检查。
- 给每个子代理的输入：方案全文、可读文件范围、该 lens 的审查目标、输出格式。输出统一为发现项列表，每条含严重度、文件/行引用、具体故障模式、影响对象、建议修法；无问题时明确说没发现阻塞项。
- 主线程负责汇总：去重、按严重度排序、把发现折进修订后的方案，再呈现给用户过关卡。子代理只补强判断，最终方案归主线程。发现项多、冲突明显时，汇总这步可单独启动一个做综合的子代理（按发现协议从 `prompts/` 选匹配的模板）。
- **不绕关卡也不切换模式**：跑计划 review 不把分析模式翻成实现模式，也不代替关卡决策；它只产出 review 结论。
- **异常降级**：子代理工具调用失败、平台规则不允许调用，或安全边界与任务冲突时，主线程按上面四个 lens 做本地第二轮自审，并在回复说明未启动子代理。
