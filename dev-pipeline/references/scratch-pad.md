# 任务记录

任务记录是实现模式的工作态记录，不是默认副作用。只在多步实现、长任务恢复、切片、回流、搁置阻塞，或用户允许记录时，在 `.dev-pipeline/<date>-<short-slug>.md` 记录流水线状态。`plan only` / `review only` / `explain only`、off-ramp 和单文件低风险任务默认不创建。

- **启用前先判定**：如果本轮只读、单步、低风险，直接跳过任务记录，并在需要时一句话说明原因。
- **重入先读回**：启用任务记录时先列 `.dev-pipeline/`，有本任务的记录就先读、接续（保住之前的模式判定、假设、已搁置阻塞、回流记录），别从零重来；找不到再新开。
- **一任务一文件**：`<date>` 用今天日期（如 `2026-06-14`），`<short-slug>` 是任务的 kebab 短描述（如 `add-oauth-refresh`）。多任务不互相覆盖，文件名自带"这是哪个任务"。
- **只依赖写文件**——不依赖 host 的 task/todo 工具，跨环境行为一致、可测。host 恰好有 task 机制时可顺带同步，但不作为依赖。
- **ephemeral**：把 `.dev-pipeline/` 加进 `.gitignore`，绝不 commit；它是工作态，不是交付物。
- **何时更新**：过每个 Stage、记下关键假设、搁置一个阻塞、切完一片、发生回流时，顺手更新对应 section。

## 模板

```markdown
# <任务一句话>

模式：分析 / 实现
当前 Stage：<1–5 或 分支名（调试/Review/TDD/文档/重构准备）>

## 关键假设
- <未澄清就推进时做的假设> → 错了改：<回头要动什么>

## 切片
- [x] <片 1>：<结论 / 已交付>
- [ ] <片 2>：<待做>

## Parked 阻塞
- <卡住什么（等谁/缺什么）> → 解除后回：Stage <N>

## 验证
- 已验证：<项 + 怎么验的>
- 未验证：<项 + 为什么没验>

## 回流记录
- Stage <N> → 退回 Stage <M>：<原因（上下文不足 / 方案站不住 / 需求理解错）>
```

每个 section 按需留空——小任务可能只用到当前 Stage 和验证两段。
