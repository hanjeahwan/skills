# 可执行指令审查

指令文档的每一句都要指导读者「做什么 / 是什么 / 何时做」。揪出只描述文档自身、不产生动作的句子，改写成正向可执行指令，循环到一次完整扫描零命中。

## 审查—改写循环

```
扫描 → 标记命中 → 改写成正向动作 → 重新扫描 → 零命中才停
                          └──── 改写可能引入新的自述 ────┘
```

## 模式

- **提案模式（默认）**：列出命中 + 建议改写，不动文件。
- **编辑模式**（用户要求改时）：应用改写，然后重新扫描确认。

## 起手扫描

先用种子模式过一遍，再逐句人工确认（模式只是定位，命不命中靠判断）：

`本流程|本 ?skill|这个 ?skill|本文档|本节|把自己当作|结对|不是.*而是|不从.*开始|并非|不属于|仔细|适当|按需|合理|高质量|健壮|重要的是|需要注意|值得一提|总之`

「重复事实来源」grep 抓不到，靠跨文件判断：写规则前先搜 CLAUDE.md/README/相邻文档有没有已经定义。

## 要揪出的反模式

1. **自我指涉 / 免责** —「本流程/本 skill 不包含…」「这个 skill 是…」：讲文档自己，不讲该做什么。
   - 改：删掉；有用信息转成动作。例：「本流程不包含特定框架规则」→「不要预设框架；先读 repo 既有约定」。
2. **persona 开场** —「把自己当作结对的资深工程师…」：角色扮演，无动作。
   - 改：删掉，直接写第一条该做的事。
3. **否定 / 对比定义** —「X 不是 A，而是 B」「不从 X 开始」：讲它不是什么。
   - 改：只说它是什么、怎么做。例：「流水线不是从读 repo 开始」→「流水线从理解用户输入开始」。
4. **空洞限定词** —「仔细/适当/按需/合理/高质量/健壮」等无可衡量标准的词：像指令，给不出可执行判据。
   - 改：换成具体判据，或删。例：「适当处理错误」→「对外部调用失败返回降级值并记日志」。
5. **填充开场** —「重要的是…/需要注意…/值得一提…/总之…」：不带指令的引子。
   - 改：删引子，只留后面的动作。
6. **重复事实来源** — 把 CLAUDE.md/README/代码/相邻文档已有的内容抄进来：会耦合、会漂移。
   - 改：指向 owner（链接或路径 + 标题），不复制；一个概念只在一处定义。

## 不要误伤（这些保留）

- **可执行禁止项**：「不要 commit」「不要预设框架」「不要 throw」——是动作约束，不是自述。
- **给子代理的任务 prompt 内部用「而不是」收窄行为边界**——是 prompt engineering（如「当作 propose-and-approve，而不是自主批量编辑」）。
- **必要的定位澄清**：读者会真找错地方时，一句澄清可留，但优先写成正向。

## 每条改写过四关

| 关 | 要求 |
|---|---|
| 正向 | 说「是什么/做什么」，不说「不是什么」 |
| 可执行 | 改变读者的动作，不只是补全描述 |
| 无损 | 原句的有用信息不丢；没用就删 |
| 最小 | 不加新概念、不加流程 |

任一关不过：要么删该句，要么重写到过关。

## 循环停止条件

改写后重新整扫一遍——改写本身可能带进新的反模式。连续一次完整扫描零命中才停。

## 输出格式

提案模式，逐条：

```
命中：<file:line>
类型：自述免责 / persona / 否定对比 / 空洞限定词 / 填充开场 / 重复来源
理由：<为什么不可执行>
改写：<正向可执行版本>
```

编辑模式：逐条应用后附 `重扫：N 处 → 0`。

零命中：`无自述型反模式`。

## 指导原则

每一句靠「改变读者做什么」挣得它的位置。描述文档自己的句子挣不到。
