# 风险关卡

主流程判定任务触及高风险面后，按本手册执行。高风险关卡用于把真实事故高发区提前暴露：数据坏、越权、回滚失败、老客户端崩、异步结果覆盖新状态。

## 触发

命中任一风险面时先进入本关卡：数据库 schema/migration/backfill/data repair、权限/auth/privacy/secret、支付/账务/admin、生产数据、队列/异步/idempotency/cache、外部 API 兼容、feature flag、发布/回滚、依赖/lockfile、`.env`、构建/部署配置、复杂 UI。

高风险关卡优先于轻量路径。单文件改 `.env`、migration、auth guard、payment config、lockfile 或部署配置，也不得进入轻量路径。

## 只读与写入

- 只读分析、review 或 plan 里提到 DB/auth/payment/production 不要求确认外部状态操作；先给判断、方案或风险评估。
- 实现、执行迁移、写生产数据、联网改状态、发送消息、付费调用、批量写入、破坏性操作必须先拿明确确认。
- 需要确认时，说明要执行的动作、影响范围、失败后果和回滚或恢复路径。

## 先列风险面

开始高风险实现前先列这些内容：

- 当前行为和目标行为。
- 受影响用户、数据、权限、外部系统和运行时资源。
- 兼容窗口：老客户端、旧数据、旧配置、灰度或 feature flag 状态。
- 回滚/前滚方案。
- 观测入口：日志、指标、审计记录、错误报告或手动检查点。
- 风险证据需求：要证明哪些风险未发生、哪些风险尚未验证、缺口会造成什么失败后果。
- 需要用户、后端、业务或安全确认的点。

## 数据变更最小要求

涉及 migration、backfill、data repair 或生产数据时，至少准备这些内容：

- 影响数据范围和筛选条件。
- 样本校验方式。
- 幂等性和失败重跑策略。
- 批量边界、限速或分片策略。
- 预演方案或本地校验目标。
- 备份、恢复来源、回滚或前滚路径。
- 半失败状态如何检测和处理。

缺少这些信息时，先交付方案和阻塞点，不执行会改外部状态的动作。

## 权限、安全和隐私

涉及 auth、权限、隐私、secret、admin、支付或账务时，先确认：

- 谁能触发该行为，谁不能触发。
- 权限校验在入口、服务端、数据层或外部系统的哪个边界执行。
- 是否可能泄露 PII、secret、token、审计日志或客户数据。
- 权限负向路径、审计记录和回归风险分别由什么证据覆盖。
- 失败时默认拒绝还是默认放行。

## 队列、异步和缓存

涉及队列、异步任务、retry、cache、idempotency 或外部回调时，先确认：

- 事件顺序、重复事件和乱序事件如何处理。
- retry 是否幂等。
- 旧异步结果是否可能覆盖新状态。
- cache 失效、回填和刷新由谁触发。
- terminal state 后还能不能产生副作用。

## 复杂 UI

复杂 UI 指带状态流、表单提交、拖拽、异步保存、权限差异、响应式关键断点或用户可见关键流程的界面。

复杂 UI 改动必须列出用户可见关键路径、关键断点、权限差异、异步保存和未验证交互的失败后果。

## 依赖、环境和发布

涉及依赖、lockfile、`.env`、构建、部署、发布或回滚时，先确认：

- 依赖和 lockfile 改动是否必要。
- 环境变量是否已有负责人和默认值。
- 构建或部署配置是否影响其它环境。
- 发布后如何观测问题。
- 回滚是否能兼容新旧数据、配置和客户端。

## 未验证风险缺口

无法证明某个风险面时，说明具体缺口、失败后果和需要谁确认；不要把缺口写成已验证。
